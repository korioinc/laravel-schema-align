# Installed replay fixtures

All example tables, columns and rows are synthetic test data. Use neutral `sample_*` identifiers and reserved `example.test` email addresses; do not add production records, personal information or real credentials. Runtime credentials must come from the explicit disposable test environment described below.

`app/` is the installed Laravel source baseline used by `InstalledAppFixture`, `MySqlInstalledFixture` and `PathPackageFixture`. Tests stage dependencies and package source locally; no runtime image is built or selected.

Run existing Composer/Pest commands with explicitly disposable loopback DB credentials. PostgreSQL requires `SCHEMA_ALIGN_TEST_DSN`, `SCHEMA_ALIGN_TEST_USER=schema_align_test`, `SCHEMA_ALIGN_TEST_PASSWORD`, and database `CREATE` for fresh replay schemas. Set `SCHEMA_ALIGN_AUTO_REPLAY_TESTS=1` or `SCHEMA_ALIGN_PATH_PACKAGE_TESTS=1` for installed/path-package checks. Set `SCHEMA_ALIGN_SUPERUSER_TESTS=1` with explicit disposable administrator credentials for superuser apply and authorization-safety scenarios.

MySQL catalog/apply tests use `SCHEMA_ALIGN_MYSQL_DSN`, `SCHEMA_ALIGN_MYSQL_USER=schema_align_test` and `SCHEMA_ALIGN_MYSQL_PASSWORD`. Administrator apply and namespace safety tests additionally require `SCHEMA_ALIGN_NAMESPACE_MYSQL_ADMIN_TESTS=1` and explicit `SCHEMA_ALIGN_MYSQL_ADMIN_USER`/`SCHEMA_ALIGN_MYSQL_ADMIN_PASSWORD`. Explicit administrator credentials target disposable infrastructure only; production uses its configured application account without substituting test credentials. Fixtures use the existing application account with original/temporary database change privileges and global inspection privileges (`SELECT`, `SHOW VIEW`, `PROCESS`, `SHOW DATABASES`, `SHOW_ROUTINE`). These inspection grants no longer prevent apply. The package does not create accounts or grant privileges; prepare only disposable test infrastructure explicitly. MySQL root/global administrative accounts and PostgreSQL superusers support approved apply; metadata visibility, plan authorization and owned cleanup checks remain required.

Fixtures allocate uniquely named resources and preserve sentinel rows and original migration history. Do not use shared/remote databases or destructive reset commands. Skipped DB checks do not prove behavior. A local container can provide an ephemeral DB server; the package runtime itself must not invoke Docker.
